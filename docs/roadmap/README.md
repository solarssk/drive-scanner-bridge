## How a plan is used

1. A plan describes the goal, the decisions already made and the work breakdown.
2. When work starts, a milestone with the version name is created and each work item
   becomes an issue in it.
3. When a plan ships, its status here changes and the result goes into the CHANGELOG.

New plans are added as `<version>-<short-name>.md` in this folder, with a row in the
table above.
