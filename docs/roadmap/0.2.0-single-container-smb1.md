# 0.2.0 roadmap: single container with an embedded SMB1/NT1 server

**Status: designed, not started.** Work on this only after 0.1.1 (stabilization of
the current two-container setup) is released. See [MAINTENANCE.md](../MAINTENANCE.md)
for the order of work and the release process.

## Why

Today the bridge runs as two containers: `smb1` (`dperson/samba`, a real Samba server
forced to the legacy SMB1/NT1 dialect, because the scanner hardware speaks nothing
else) and `drive-uploader` (this repo's Python service). The goal of 0.2.0 is **one
container**, without giving up the hardening the uploader has today.

Merging the two *as they are* was researched and rejected (see "Rejected options").
The only option that is not a security regression is to replace Samba with a small,
purpose-built SMB1 server embedded in the uploader process.

## Settled decisions (do not re-litigate)

1. **Both ports.** Serve port 445 (direct SMB over TCP) and port 139 (NetBIOS Session
   Service). The scanner's real port is unknown (no access to the hardware), so cover both.
2. **One extra capability.** Add exactly `CAP_NET_BIND_SERVICE` to the container
   (`cap_drop: [ALL]` stays, plus `cap_add: [NET_BIND_SERVICE]`) to bind the privileged
   ports. The scanner's target port is fixed, so a port remap is not possible.
3. **Hard cutover.** Delete the `smb1` service in the same change. No dual-mode toggle.
   `drive-uploader` joins `smb1_network` with the static IP `smb1` used to have; that
   network exists so scanner traffic does not share the NAS's main interface (where DSM
   runs its own SMB service on 445/139).
4. **Hand-rolled, stdlib only.** No Impacket, no third-party SMB library.

## Rejected options (with reasons)

### Samba + uploader in one image under a supervisor (s6-overlay)
- Samba needs a shell, many C libraries and writable state directories, so the final
  image can no longer be distroless and `read_only: true` is lost.
- `smbd` needs at least `NET_BIND_SERVICE`, `DAC_OVERRIDE`, `SETUID`, `SETGID` (plus
  `CHOWN`/`FOWNER` unless disabled) instead of zero capabilities.
- The network boundary between the legacy SMB1 listener and the process holding the
  Synology credentials disappears.
- One `HEALTHCHECK` for two independent processes; a crash-looping uploader would leave
  smbd silently accepting scans that never upload.
- The Docker Scout/Trivy result stops being a structural property of a distroless
  image and becomes a standing patch-and-rescan obligation (Samba has had CVSS 9.9-10.0
  CVEs in recent years, e.g. CVE-2021-44142, CVE-2025-10230).
- The only gain is one fewer line in docker-compose.yml.

### Embedding Impacket's `smbserver.py`
- It is the only maintained Python SMB *server* library (`pysmb` and `smbprotocol` are
  client-only; `twsmb` is abandoned and SMB2-focused), but it is a ~5700-line general
  SMB1/2/3 + RPC codebase built for offensive tooling.
- It has a real server-side path-traversal CVE in exactly the failure mode that matters
  here (CVE-2021-31800, CVSS 9.3, write path; fixed in 0.9.23).
- `setSMB2Support(False)` only changes what is advertised; the SMB2/3, RPC and
  named-pipe code stays loaded and reachable.
- No evidence of anyone running it as a standing production listener.

## Design

New package `uploader/scanner_drive_bridge/smb1_server/`, roughly 700-950 lines in
8 files, split by concern so the security-sensitive parsing can be reviewed alone:

```
smb1_server/
    __init__.py     # exports SMB1Server
    errors.py       # ProtocolError, NT status constants
    wire.py         # SMB header codec, word/byte-block helpers, AndX chain build/parse
    netbios.py      # NBSS SESSION REQUEST/RESPONSE + NetBIOS name encoding (port 139 only)
    framing.py      # shared 4-byte length-prefixed message read/write (both ports, post-handshake)
    files.py        # sanitize_filename, IncomingFileWriter (temp buffer -> atomic promote)
    connection.py   # ConnectionState / Session / Tree / OpenFile, per-connection serve loop
    commands.py     # the command handlers + LOCKING_ANDX stub, DISPATCH table
    server.py       # SMB1Server: dual-port listen, accept loop, thread-per-connection, start()/stop()
```

Concurrency: **thread-per-connection** (`threading`). The codebase has no async
infrastructure, there is one legacy scanner, and sequential per-connection parsing keeps
the WRITE_ANDX bounds checking easy to reason about.

### Protocol scope

Commands: NEGOTIATE (0x72), SESSION_SETUP_ANDX (0x73), TREE_CONNECT_ANDX (0x75),
NT_CREATE_ANDX (0xA2), WRITE_ANDX (0x2F), CLOSE (0x04), TREE_DISCONNECT (0x71),
LOGOFF_ANDX (0x74), and LOCKING_ANDX (0x24) as a spec-legal stub that replies
STATUS_NOT_SUPPORTED (a reply, not a dropped connection).

- **NEGOTIATE**: advertise only `NT LM 0.12`. If the client does not offer it, reply
  `DialectIndex = 0xFFFF`. `SecurityMode = 0` (no signing/encryption, matching today's
  Samba config). Do **not** advertise `CAP_LARGE_WRITEX`: every WRITE_ANDX then has the
  12-word form and at most 65535 bytes of data, which shrinks the bounds-check surface.
- **SESSION_SETUP_ANDX**: no NTLM/LM verification; grant a UID for the configured
  identity (or anonymous). **`smb1_network` isolation becomes the entire access control**
  for the share. Say so in the README Security section so nobody mistakes
  `SMB_USERNAME` for a credential check.
- **NT_CREATE_ANDX**: always reply `OplockLevel = 0`, which sidesteps oplock-break
  handling entirely. With `FLAGS2_UNICODE`, names are 2-byte aligned relative to the
  **start of the SMB header**, not to the byte block.
- AndX chaining (SESSION_SETUP_ANDX + TREE_CONNECT_ANDX in one packet) must work; real
  clients send it. The response builder patches each stage's `AndXOffset`.
- Not implemented on purpose: SMB2/3, RPC/IPC$/named pipes, TRANSACTION*/NT_TRANSACT*,
  directory listing, real NTLM/Kerberos. They are unreachable because they do not exist,
  not because they are configured off.

### Framing

Port 445 uses the same 4-byte NBSS-style header as port 139 (type `0x00` = SESSION
MESSAGE, then flags with the length-extension bit, then a 2-byte big-endian length). It
only skips the SESSION REQUEST / POSITIVE RESPONSE handshake. One shared
`read_smb_message` / `write_smb_message` pair therefore serves both ports after the
(port-139-only) handshake. **Verify this against the spec and a packet capture of
`smbclient -p 445` before trusting it.** A wrong assumption would silently desync every
message after the first.

### WRITE_ANDX: the critical path

```python
def handle_write_andx(conn, header, body, *, raw_packet):
    words, _ = parse_word_block(body, 0)
    if len(words) != 12:
        raise ProtocolError("unexpected WRITE_ANDX word count")
    fid, write_offset = words[3], words[4]
    data_length, data_offset = words[9], words[10]   # data_offset is attacker controlled

    packet_len = len(raw_packet)
    # Validate BEFORE touching the buffer. raw_packet[a:b] silently clamps instead of
    # raising when b > len(raw_packet), so a naive slice would quietly return fewer
    # bytes than the header claims and corrupt the file with no signal.
    if data_offset < SMB_HEADER_SIZE or data_offset > packet_len:
        raise ProtocolError("WRITE_ANDX DataOffset out of range")
    end = data_offset + data_length
    if end > packet_len:
        raise ProtocolError("WRITE_ANDX overruns packet")

    open_file = conn.files.get(fid)
    if open_file is None or open_file.tree.tid != header.tid:
        return build_error_response(header, STATUS_INVALID_HANDLE)
    open_file.handle.write(write_offset, raw_packet[data_offset:end])
    ...
```

This is the integer under/overflow bug class behind the EternalBlue family, so it gets
the adversarial test suite below, not just happy-path tests. A connection that drops
(socket error, idle timeout, TREE_DISCONNECT without CLOSE) must **abort**, never
promote, every open file; that cleanup lives in `connection.py`'s `finally` block.

### File materialization

Existing code that must stay unchanged: `scanner.py`'s `StabilityTracker` only looks at
`Path.stat()` (size + mtime unchanged across N checks spaced by an interval) and ignores
dot-prefixed names and the suffixes `.tmp .part .partial .crdownload`.

- Buffer each transfer in a hidden temp file **directly inside `/incoming`**, named
  `.smb-<uuid>.partial` (invisible to the tracker on two independent grounds).
- `/incoming` and `/data` are two separate named volumes, so a cross-volume rename is not
  guaranteed atomic. Never stage in `/data`.
- On CLOSE: `flush()` + `os.fsync()` + `os.rename()` into the final name (same device,
  atomic). The file then appears with its final size and a single mtime, and settles in
  the minimum `stability_checks * stability_interval_seconds`.
- `sanitize_filename`: strip directory components (flat share), reject `..`, NUL,
  absolute paths, and names that the tracker would never see (dot/`~` prefix, ignored
  suffixes). Reject loudly instead of silently swallowing the scanner's file.

### Integration

- `config.py`: new fields on the frozen `Config` dataclass:
  `smb_enabled=True`, `smb_bind_host="0.0.0.0"`, `smb_ports=[445, 139]`,
  `smb_share_name="printshare"`, `smb_username="prt01"`, `smb_server_name="UPLOADER"`.
  Env: `SMB_ENABLED`, `SMB_BIND_HOST`, `SMB_PORTS`, `SMB_SHARE_NAME`, `SMB_USERNAME`,
  `SMB_SERVER_NAME`. Rename `_get_seconds_list` to `_get_int_list` (it parses any int list).
- `main.py`: start `SMB1Server` as daemon threads before the blocking
  `worker.run_forever()`; stop it from the existing signal handler and in a `finally`.
  `Worker` itself is untouched, so existing tests keep working unmodified.
- `SMB1Server.stop()`: set an Event, close the listening sockets (unblocks `accept()`),
  close tracked live connection sockets.

### Compose and image

- Remove the `smb1` service and `depends_on: smb1`. Keep `smb1_network` as
  `external: true`.
- `drive-uploader`: keep `read_only`, `no-new-privileges`, `cap_drop: [ALL]`; add
  `cap_add: [NET_BIND_SERVICE]`; attach to `default` **and** `smb1_network` with
  `ipv4_address: ${SMB1_STATIC_IP:?...}`. No `ports:` block (the scanner dials the
  container IP on the custom network).
- Drop `SMB_PRT01_PASSWORD` from `.env.example` and from the `compose-lint` job's
  placeholder `.env`. This is a real behavior change: the new server verifies no password.
- Image tag `0.2.0`. No Dockerfile change is expected (stdlib only). Before wiring compose,
  confirm in isolation: `docker run --cap-drop=ALL --cap-add=NET_BIND_SERVICE --user 1048:100 ...`
  can bind a port below 1024 as a non-root UID.
- Base image: 0.1.1 moves the runtime to `distroless/python3-debian13` + Python 3.13 with
  both bases pinned by digest (the debian12 image never picked up Debian's fixes and kept
  the weekly image scan red; see issue #17 and PR #23). Build the SMB server on that base;
  it is stdlib only, so nothing in the design depends on the Python minor version.

## Tests

New `uploader/tests/smb1_server/`, in the repo's existing style (local fakes, no mock
libraries, drive the loop manually):

- `test_wire.py`: header round trip, word/byte-block parsing, AndX offset patching, a
  crafted out-of-range `AndXOffset` must raise `ProtocolError`, not `IndexError`.
- `test_netbios.py`: name encoding against **pinned known-good byte strings** (not just a
  self-consistent round trip), SESSION REQUEST parsing, the length-extension bit (> 65535).
- `test_write_andx_bounds.py` (highest value): DataOffset before the header; DataOffset ==
  packet length with non-zero DataLength; overrun by one byte; DataLength 0xFFFF on a tiny
  packet; wrong word count; unknown FID; one conforming write as a positive control.
- `test_files.py`: `../../etc/passwd`, `..\..\windows\system32`, absolute paths, embedded
  NUL, `SCN_0001.tmp`; the final file must not appear in a directory listing until
  `close_and_promote()` returns.
- `test_server_integration.py`: full session over sockets on ephemeral ports (never
  445/139, so CI needs no privileges).
- `test_fuzz.py`: stdlib `random`, fixed seed, ~20k iterations against the WRITE_ANDX and
  NEGOTIATE parsers; anything but a clean `ProtocolError` is a bug. `hypothesis` is an
  optional dev-only follow-up.
- **Real-client test in CI**: a job that installs `smbclient` (CI-time only, never in the
  runtime image) and runs
  `smbclient //127.0.0.1/printshare -p <port> --max-protocol=NT1 -N -c "put file name"`
  against the server on an unprivileged port, then checks the file landed. An independent
  client catches byte-order/padding bugs that a self-consistent test cannot.

## Order of work

1. Wire/codec layer + unit tests (CI only).
2. Command handlers, files, connection + unit tests, especially the WRITE_ANDX suite (CI only).
3. Fuzz suite (CI only).
4. `server.py` + the `smbclient` integration job (CI only).
5. `main.py` / `config.py` integration; run the packaged image locally with
   `--cap-add=NET_BIND_SERVICE --user 1048:100` and confirm a file travels
   smbclient -> `/incoming` -> Synology Drive.
6. docker-compose / `.env.example` cutover; `docker compose config` in CI.
7. Deploy to the NAS; `drive-uploader` takes over the static IP, `smb1` is removed.
   Human step, still without the scanner.
8. **Owner connects the real scanner and reports what breaks.** Nothing earlier can
   substitute for this.

Work in small PRs (one per step), each tied to an issue in the `0.2.0` milestone.

## What only the real scanner can tell us

- The actual port (445 vs 139).
- Exact SESSION_SETUP_ANDX / NT_CREATE_ANDX field values (native OS string, capability
  flags, PID/MID sequencing across AndX chains).
- Firmware quirks: retry timing, reaction to `OplockLevel = 0`, tolerance for
  `SecurityMode = 0`, per-request timeouts when a large scan arrives as hundreds of
  65535-byte writes.

## Risks to double-check while implementing

- Port 445 framing (see above): confirm with a capture.
- UID/TID/MID/PID handling across AndX chains; clients may reuse a UID across several
  TREE_CONNECT_ANDX calls and MIDs are not guaranteed monotonic. Low blast radius (one
  client), but watch it in step 8.
- NetBIOS first-level name encoding: verify byte-for-byte against a real capture, since
  the suffix byte (0x20/0x00/0x03) or nibble order can be subtly wrong while
  encode/decode tests still pass.
- Unicode alignment padding: the pad is relative to the SMB header start; test with an
  intentionally odd-length preceding field so the pad byte actually matters.
- Authentication is nominal: `smb1_network` is the whole access boundary.
